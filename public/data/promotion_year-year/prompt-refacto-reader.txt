Objectif
Nous implémentons maintenant le nouveau système de lecture des référentiels JSON.
Architecture déjà décidée. Pas de discussion conceptuelle supplémentaire.

Contraintes techniques (non négociables)

- PHP 8.2 uniquement.
- Symfony.
- Dataset root paramétrable via un paramètre (par défaut %kernel.project_dir%/public/data).
- Structure :
  public/data/{promotion}_{year}/
    - structure.json
    - content/{type}/{code}.json
- Tous les dossiers et fichiers sont en minuscules.

Politique de comportement (figée)

1) Validation
- promotion et year validés strictement.
- tentative invalide → exception.
- path traversal interdit.

2) Dataset root ou structure.json absent
- → DatasetNotFound exception (hard failure).

3) Fichier content absent
- → politique tolérante :
  - return null (ressource unique) ou [] (collection),
  - ajouter un warning au collector,
  - ne jamais lever d’exception.

4) JSON invalide (content)
- warning + return null/[].

5) JSON invalide (structure)
- exception.

Cache

- Cache activé dès la V1.
- Deux niveaux :
  - in-request memory cache.
  - cache Symfony dédié.
- Invalidation par mtime :
  - la clé de cache doit inclure filemtime.
  - aucun TTL arbitraire.

Warnings

- Collector request-scoped.
- Les Readers ajoutent les warnings.
- Aucun Flash dans les services.
- Les Flash seront gérés plus tard par un subscriber dédié (hors scope immédiat).

Séparation stricte

- Readers = lecture technique uniquement.
- FrameworkProvider = relations uniquement.
- AnalyticsService = agrégations pour graphes.
- Aucun code UI dans ces services.
